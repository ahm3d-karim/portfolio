Case study · macro lens

Reading South Asia honestly

Five economies. Four decades. One honest look. Macro Lens publishes macroeconomic dossiers for Pakistan, India, Bangladesh, Sri Lanka, and Nepal, every series pulled straight from the World Bank's World Development Indicators. No backend, no database, no aggregator.

The whole product is a static export. Data lives as JSON files; pages are pre-rendered at build time. That means the site cannot go down because a data API did, cannot leak a database, and loads like a document, not like an app.

The editorial rule: finding first

Most data dashboards show metrics and make the reader do the analysis. Macro Lens inverts that. Every chart on the site answers a written question, and the finding is the headline. Pakistan's page leads with the boom-bust cycle and remittance dependence. Bangladesh's leads with the export machine that carried its GDP per capita past Pakistan's. Sri Lanka's leads with the 2022 reserve collapse. Nepal's leads with remittances worth roughly a quarter of GDP.

A chart that does not answer a question does not ship.

That rule came from economics training: a figure in a paper exists to support a claim. If you cannot write the claim, you do not yet have a figure.

The pipeline

A sibling data repo pulls each series from the WDI API, checks it, and writes versioned JSON. The site repo treats that data as a build input, so refreshing the numbers is a pipeline run, not a code change. Primary source only: every series is traceable to the World Bank, never to a scraped aggregator. (A known limitation, stated plainly: some World Bank government-finance series for Pakistan are absent at source, and one alternative API is unreachable from my network, so those series ship empty rather than filled with a proxy.)

The stack is deliberately boring: Next.js 16 with static output, TypeScript, Recharts, Tailwind. The interesting decisions are editorial and architectural, not framework-shaped.

What I learned

Static-first is a data-product superpower: the entire failure surface of a live API disappears when the build does the fetching. And constraint breeds voice: the "finding first" rule made five country pages feel like five arguments, not five dashboards.
